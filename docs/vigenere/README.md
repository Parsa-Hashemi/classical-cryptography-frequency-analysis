# بخش رمز ویژنر - پروژهٔ ۹

در این بخش رمز ویژنر پیاده‌سازی شده است. علاوه بر رمزگذاری و رمزگشایی با کلید، امکان شکستن رمز بدون کلید، تحلیل آماری متن و اجرای آزمایش نرخ موفقیت هم وجود دارد.

## پیاده‌سازی

کد به چند قسمت جدا تقسیم شده است:

- `vigenere_cipher.py` برای رمزگذاری و رمزگشایی است.
- `vigenere_cryptanalysis.py` محاسبات مربوط به شکستن رمز را انجام می‌دهد.
- `text_statistics.py` آمار متن و نمودارها را می‌سازد.
- `experiment.py` برای اجرای چند آزمایش با طول‌های مختلف استفاده می‌شود.

## ساختار فایل‌ها

- `src/vigenere_cipher.py`: رمزگذاری و رمزگشایی با کلید معلوم
- `src/vigenere_cryptanalysis.py`: شاخص تطابق، آزمون کاسیسکی، تخمین طول کلید، بازیابی کلید و شکستن رمز
- `src/text_statistics.py`: جدول و نمودار فراوانی حرف، دوگرام و سه‌گرام
- `src/experiment.py`: آزمایش نرخ موفقیت رمز‌شکنی برحسب طول متن
- `main.py`: رابط خط فرمان برای اجرای همهٔ بخش‌ها
- `tests/test_vigenere.py`: تست‌های خودکار
- `data/sample_plaintext.txt`: پیکرهٔ نمونه برای آزمایش

## مدل‌سازی ریاضی و اثبات‌ها

در محاسبات، حروف انگلیسی با اعضای مجموعهٔ پیمانه‌ای زیر نمایش داده می‌شوند:

```text
Z_26 = {0, 1, 2, ..., 25}
```

مدل می‌شوند؛ یعنی `A = 0`، `B = 1`، ... و `Z = 25`. فاصله، عدد، نشانه‌ها و حروف غیرانگلیسی وارد این مدل نمی‌شوند و در برنامه بدون تغییر باقی می‌مانند.

### ۱. مدل ریاضی رمزگذاری و رمزگشایی

فرض کنید متن اصلی دنبالهٔ `P_0, P_1, ..., P_(n-1)` و کلید دارای طول `m` و برابر دنبالهٔ `K_0, K_1, ..., K_(m-1)` باشد. کلید به‌صورت دوره‌ای تکرار می‌شود؛ بنابراین حرف کلید مورد استفاده در جایگاه `i` برابر `K_(i mod m)` است.

```text
Encryption: C_i = (P_i + K_(i mod m)) mod 26
Decryption: P'_i = (C_i - K_(i mod m)) mod 26
```

#### اثبات درستی رمزگشایی

فرمول رمزگذاری را داخل فرمول رمزگشایی قرار می‌دهیم:

```text
P'_i = ((P_i + K_(i mod m)) - K_(i mod m)) mod 26
     = P_i mod 26
     = P_i
```

چون `P_i` از ابتدا عددی بین ۰ و ۲۵ است، `P_i mod 26` همان `P_i` خواهد بود. پس برای تمام جایگاه‌ها `P'_i = P_i` و در نتیجه:

```text
Decrypt(Encrypt(P, K), K) = P
```

این همان دلیل ریاضی تست رفت‌وبرگشت رمزگذاری و رمزگشایی در پروژه است.

### ۲. چرا Brute Force عملی نیست؟

اگر طول کلید `m` معلوم باشد، برای هر یک از `m` جایگاه کلید ۲۶ انتخاب مستقل وجود دارد. طبق اصل ضرب، تعداد کلیدهای ممکن برابر است با:

```text
|K_m| = 26 × 26 × ... × 26 = 26^m
```

اگر طول کلید نیز معلوم نباشد و همهٔ طول‌های ۱ تا `M` امتحان شوند، تعداد کلیدها برابر مجموع هندسی زیر است:

```text
26^1 + 26^2 + ... + 26^M = (26^(M+1) - 26) / 25
```

رشد این تعداد نمایی است. چند نمونه:

| طول کلید | تعداد کلیدهای ممکن | زمان خوش‌بینانه با یک میلیارد کلید در ثانیه |
|---:|---:|---:|
| ۵ | `26^5 = 11,881,376` | حدود ۰٫۰۱۲ ثانیه |
| ۸ | `26^8 = 208,827,064,576` | حدود ۳٫۵ دقیقه |
| ۱۲ | `26^12 = 95,428,956,661,682,176` | بیش از ۳ سال |
| ۱۶ | `26^16 = 43,608,742,899,428,874,059,776` | حدود ۱٫۳۸ میلیون سال |

این برآورد حتی هزینهٔ واقعی رمزگشایی و تشخیص انگلیسی بودن خروجی را نادیده می‌گیرد. رمزگشایی هر کلید برای متنی با `n` حرف به `O(n)` عملیات نیاز دارد؛ بنابراین مرتبهٔ زمانی جست‌وجوی کامل در واقع:

```text
O(n × 26^m)
```

است. پس روش brute force فقط برای کلیدهای بسیار کوتاه عملی است. روش آماری پروژه به‌جای بررسی `26^m` کلید، ابتدا طول کلید را تخمین می‌زند و سپس هر ستون را مانند یک رمز سزار مستقل با تنها ۲۶ انتقال بررسی می‌کند. برای یک طول کلید مشخص، قسمت بازیابی حروف کلید تقریباً `26 × m` حالت را می‌سنجد؛ این کاهش، علت عملی بودن حملهٔ آماری است.

### ۳. مدل شاخص تطابق (Index of Coincidence)

اگر در متنی با `N` حرف، فراوانی حرف `j` برابر `f_j` باشد، شاخص تطابق از رابطهٔ زیر محاسبه می‌شود:

```text
IC = sum(f_j × (f_j - 1)) / (N × (N - 1))
```

#### اثبات فرمول IC

از میان `N` حرف، یک حرف را انتخاب می‌کنیم. `N × (N - 1)` زوج مرتب از دو جایگاه متفاوت وجود دارد. برای حرف `j` نیز `f_j × (f_j - 1)` زوج مرتب وجود دارد که هر دو عضو آن حرف `j` هستند. با جمع‌کردن این مقدار برای تمام ۲۶ حرف و تقسیم بر تعداد کل زوج‌ها، احتمال یکسان‌بودن دو حرف تصادفی به دست می‌آید؛ این احتمال دقیقاً همان IC است.

برای توزیع کاملاً یکنواخت، احتمال هر حرف `1/26` است، پس:

```text
IC_uniform = 26 × (1/26)^2 = 1/26 ≈ 0.0385
```

در زبان انگلیسی حروف توزیع یکنواخت ندارند و IC معمولاً نزدیک `0.066` است. همین اختلاف امکان تشخیص ستون‌های شبیه متن انگلیسی را فراهم می‌کند.

#### چرا IC طول کلید را آشکار می‌کند؟

اگر طول حدس‌زده‌شده همان طول واقعی `m` باشد، حروف جایگاه‌های هم‌نهشت `i mod m` همگی با یک انتقال سزار رمز شده‌اند. انتقال سزار فقط نام حروف را جابه‌جا می‌کند و برابری دو حرف و شکل کلی توزیع فراوانی را حفظ می‌کند؛ بنابراین IC هر ستون باید به IC زبان انگلیسی نزدیک باشد.

اگر طول اشتباه انتخاب شود، معمولاً حروفی که با انتقال‌های متفاوت رمز شده‌اند در یک ستون مخلوط می‌شوند. این اختلاط توزیع را یکنواخت‌تر و IC را به `1/26` نزدیک‌تر می‌کند. به همین دلیل برنامه میانگین IC ستون‌ها را برای طول‌های مختلف مقایسه می‌کند. البته مضرب‌های طول واقعی نیز ممکن است IC بالایی داشته باشند؛ به همین علت IC به‌تنهایی کافی نیست.

### ۴. مدل آزمون کاسیسکی

اگر یک `n-gram` یکسان در متن اصلی دو بار ظاهر شود و هر دو بار از یک جایگاه دوره‌ای کلید شروع شوند، دنبالهٔ کلید استفاده‌شده برای آن‌ها یکسان است؛ پس متن رمز یکسانی تولید می‌کنند. یکسان‌بودن جایگاه دوره‌ای یعنی فاصلهٔ دو رخداد بر طول کلید `m` بخش‌پذیر باشد:

```text
distance ≡ 0 (mod m)
```

بنابراین عوامل مشترک فاصلهٔ سه‌گرام‌ها، چهارگرام‌ها و پنج‌گرام‌های تکراری، نامزدهای خوبی برای طول کلید هستند. این استدلال قطعی نیست، چون بعضی تکرارها می‌توانند تصادفی باشند؛ در نتیجه برنامه امتیاز کاسیسکی را با IC ترکیب می‌کند.

### ۵. مدل کای‌دو برای بازیابی هر حرف کلید

پس از تعیین طول کلید، هر ستون یک رمز سزار است. برای هر انتقال احتمالی `s` از ۰ تا ۲۵، ستون رمزگشایی می‌شود. اگر تعداد مشاهده‌شدهٔ حرف `j` برابر `O_j` و تعداد مورد انتظار آن طبق فراوانی انگلیسی برابر `E_j = N × p_j` باشد، امتیاز کای‌دو چنین است:

```text
chi_square(s) = sum((O_j - E_j)^2 / E_j)
```

انتقالی انتخاب می‌شود که کمترین امتیاز را داشته باشد:

```text
best_shift = argmin_s chi_square(s)
```

دلیل انتخاب کمینه این است که در انتقال درست، فراوانی مشاهده‌شده به فراوانی مورد انتظار انگلیسی نزدیک‌تر است؛ پس اختلاف‌های `O_j - E_j` و در نتیجه مجموع کای‌دو کوچک‌تر می‌شوند.

### ۶. مدل آنتروپی شانون و فراوانی n-gramها

برای توصیف میزان پراکندگی حروف از آنتروپی شانون استفاده می‌شود. اگر احتمال تجربی حرف `j` برابر `p_j = f_j/N` باشد:

```text
H(X) = -sum(p_j × log2(p_j))
```

اگر فقط یک حرف وجود داشته باشد، احتمال آن ۱ و آنتروپی صفر است. بیشترین آنتروپی برای توزیع یکنواخت ۲۶ حرف رخ می‌دهد و برابر `log2(26) ≈ 4.70` بیت بر حرف است. برنامه آنتروپی متن اصلی و متن رمز را محاسبه می‌کند و اختلاف آن‌ها را در یک گزارش JSON می‌نویسد. علاوه بر تک‌حرف‌ها، فراوانی دوگرام‌ها و سه‌گرام‌ها نیز محاسبه می‌شود تا ساختار زبانی متن‌های کاندید بهتر سنجیده شود.

### ۷. مدل آزمایش نرخ موفقیت

برای هر طول متن `L`، حمله `T` بار روی نمونه‌ها و کلیدهای تصادفی اجرا می‌شود. اگر `S` بار کلید یا متن دقیقاً بازیابی شود، نرخ موفقیت تجربی برابر است با:

```text
success_rate(L) = S / T
```

علاوه بر بازیابی کامل کلید و متن، درصد حروف درست هر trial نیز محاسبه و میانگین گرفته می‌شود:

```text
average_letter_accuracy(L) = sum(correct_letters_t / L) / T
```

بنابراین نمودار سه خط `Average letter accuracy`، `Exact plaintext recovery` و `Exact key recovery` دارد. این اعداد برآوردی تجربی از کیفیت حمله برای آن طول متن هستند. استفاده از seed ثابت باعث می‌شود نمونه‌گیری و نمودار آزمایش قابل تکرار باشند. با افزایش طول متن، فراوانی‌های مشاهده‌شده پایدارتر می‌شوند و معمولاً نرخ موفقیت افزایش می‌یابد.

## خلاصهٔ روش رمز‌شکنی

1. فقط حروف A-Z برای محاسبات آماری جدا می‌شوند.
2. میانگین IC ستون‌ها برای طول‌های کاندید محاسبه می‌شود.
3. فاصلهٔ n-gramهای تکراری در آزمون کاسیسکی فاکتورگیری می‌شود.
4. ترکیب امتیاز IC، کاسیسکی و جریمهٔ پیچیدگی، طول‌های محتمل را رتبه‌بندی می‌کند.
5. هر ستون با آزمون کای‌دو روی ۲۶ انتقال ممکن شکسته می‌شود.
6. متن‌های کاندید با فراوانی حروف، دوگرام‌ها، سه‌گرام‌ها و کلمات رایج انگلیسی مقایسه می‌شوند.

## اجرا

دستورها را داخل پوشهٔ `vigenere_project` اجرا کنید.

برای اجرای ساده و تعاملی، برنامه را بدون آرگومان اجرا کنید:

```powershell
python main.py
```

یک منوی انگلیسی ساده نمایش داده می‌شود و برنامه ورودی‌ها را مرحله‌به‌مرحله می‌پرسد. روش‌های خط فرمان زیر نیز برای اجرای مستقیم و قابل‌تکرار همچنان فعال‌اند.

رمزگذاری:

```powershell
python main.py encrypt --text "Attack at dawn!" --key LEMON
python main.py encrypt --input data/sample_plaintext.txt --key LOGIC --output output/ciphertext.txt
```

رمزگشایی با کلید معلوم:

```powershell
python main.py decrypt --text "Lxfopv ef rnhr!" --key LEMON
python main.py decrypt --input output/ciphertext.txt --key LOGIC --output output/plaintext.txt
```

شکستن رمز بدون داشتن کلید:

```powershell
python main.py break --input output/ciphertext.txt --max-key-length 15 --output output/recovered.txt
```

ساخت جدول‌های JSON و نمودار حرف/دوگرام/سه‌گرام:

```powershell
python main.py analyze --input output/ciphertext.txt --label ciphertext --output-dir output
```

مقایسهٔ آنتروپی شانون متن اصلی و متن رمز:

```powershell
python main.py compare-entropy --plaintext-input data/sample_plaintext.txt --ciphertext-input output/ciphertext.txt --output output/entropy_comparison.json
```

رسم نمودار نرخ موفقیت نسبت به طول متن:

```powershell
python main.py experiment --corpus data/sample_plaintext.txt --lengths 100 200 400 800 1200 --trials 20 --output-dir output
```

برای نمودارها ابتدا وابستگی را نصب کنید:

```powershell
python -m pip install -r requirements.txt
```

اجرای تست‌ها:

```powershell
python -m unittest discover -s tests -v
```

## نکات مهم

- IC متن انگلیسی معمولاً نزدیک ۰٫۰۶۶ و متن یکنواخت نزدیک `1/26` است.
- طول‌های مضرب طول واقعی نیز ممکن است IC بالایی داشته باشند؛ به همین دلیل شواهد کاسیسکی، جریمهٔ پیچیدگی و امتیاز زبانی با هم استفاده شده‌اند.
- با کوتاه بودن متن، جدول فراوانی نویزی است و احتمال خطا در طول کلید یا حروف آن بالا می‌رود.
- دو معیار سخت‌گیرانهٔ آزمایش، برابری کامل کلید و متن بازیابی‌شده هستند؛ خط دقت حرفی نیز میزان بازیابی جزئی را جداگانه نشان می‌دهد.
- این پیاده‌سازی کلاسیک روی الفبای انگلیسی A-Z کار می‌کند. فاصله، علائم، عددها و حروف فارسی را تغییر نمی‌دهد و آن‌ها باعث جلو رفتن کلید نمی‌شوند.
